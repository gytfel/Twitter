# Автопостинг в X (Twitter)

Бот сам публикует посты в твой аккаунт по расписанию. Твоё участие — один раз настроить.

**Что внутри**

- публикация через официальный X API v2 (`POST /2/tweets`), tweepy
- два источника текста: готовый список постов или генерация через Claude API
- защита от дублей (X отклоняет одинаковые твиты) и жёсткий лимит постов в сутки
- случайный сдвиг времени, чтобы посты не выходили секунда-в-секунду
- ретраи с backoff, обработка 429 / 401 / 403, логи в файл

## ⚠️ Сначала прочитай про деньги

В феврале 2026 X перевёл API на оплату за запрос, и **бесплатного тарифа для новых
разработчиков больше нет**. Старый free-тариф на 1500 постов в месяц закрыт для
новых аккаунтов, Basic ($200/мес) отменён, Pro закрыт для новых регистраций.

Ориентировочные цены pay-per-use (проверь актуальные на developer.x.com, они менялись
уже дважды за год):

| Действие | Примерно |
|---|---|
| публикация поста | ~$0.015 |
| **публикация поста со ссылкой** | **~$0.20** |
| чтение поста | ~$0.005 |

Что это значит на практике: 3 поста в день без ссылок ≈ **$1.4/мес**. Те же 3 поста
**со ссылками** ≈ **$18/мес**. Если планируешь постить ссылки — считай заранее.

Ещё одно следствие: чтение стоит денег, поэтому бот ничего не читает — вся история
публикаций хранится локально в `history.json`.

## Установка

### 1. Ключи X API

1. Зайди на [developer.x.com](https://developer.x.com), создай проект и приложение.
2. **User authentication settings** → App permissions: **Read and Write**. Тип приложения — Web App / Automated App.
3. **Keys and tokens** → сгенерируй API Key, API Secret, Access Token, Access Token Secret.

> Самая частая ошибка: сначала выпустили токены, потом поменяли права на Read and Write.
> Старые токены остаются read-only. **Перевыпусти Access Token после смены прав.**

### 2. Проект

```bash
pip install -r requirements.txt
cp .env.example .env
nano .env          # вставь ключи
```

### 3. Тексты постов

Открой `posts.txt`, замени примеры на свои. Посты разделяются строкой `---`.
Строки с `#` — комментарии.

Хочешь бесконечный контент вместо списка — поставь в `.env`:

```
CONTENT_MODE=ai
ANTHROPIC_API_KEY=sk-ant-...
ACCOUNT_TOPIC=о чём твой аккаунт
```

Ключ Claude API берётся на [console.anthropic.com](https://console.anthropic.com),
он оплачивается отдельно от подписки Claude.ai.

### 4. Проверка (пока без публикации)

В `.env` уже стоит `DRY_RUN=true` — бот работает вхолостую и ничего не отправляет.

```bash
python main.py check      # рабочие ли ключи + расписание на сегодня
python main.py preview    # показать текст следующего поста
python main.py once       # весь цикл, но твит не уйдёт
```

В режиме `DRY_RUN=true` бот не пишет в `history.json`: холостые прогоны не расходуют
суточный лимит и не «сжигают» посты из `posts.txt`. Гонять `once` для проверки можно
сколько угодно раз.

Когда всё нравится — поставь `DRY_RUN=false`.

Коды возврата `once` (пригодится для cron и мониторинга):

| Код | Что значит |
|---|---|
| `0` | пост опубликован **или** штатно пропущен по суточному лимиту |
| `1` | ошибка: не получен текст, неверные ключи, публикация не удалась |

## Запуск в режиме «работает само»

### Вариант А: GitHub Actions (бесплатно, без сервера)

Готовый workflow уже лежит в `.github/workflows/autopost.yml`.

1. Залей репозиторий на GitHub (**приватный** — там будет история постов).
2. Settings → Secrets and variables → Actions → добавь `X_API_KEY`, `X_API_SECRET`,
   `X_ACCESS_TOKEN`, `X_ACCESS_TOKEN_SECRET` (и `ANTHROPIC_API_KEY`, если режим `ai`).
3. Проверь `cron` в workflow — **время указывается в UTC**. Для Хельсинки летом вычитай 3 часа.

Учти: расписание GitHub Actions может опаздывать на 5–20 минут под нагрузкой. Для постинга это неважно.

### Вариант Б: свой сервер / VPS, systemd

```bash
sudo tee /etc/systemd/system/autopost.service > /dev/null << 'EOF'
[Unit]
Description=X autopost bot
After=network-online.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/twitter-autopost
ExecStart=/usr/bin/python3 main.py run
Restart=always
RestartSec=60

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now autopost
journalctl -u autopost -f       # смотреть логи
```

### Вариант В: cron

```cron
0 10,15,20 * * * cd /home/user/twitter-autopost && /usr/bin/python3 main.py once >> cron.log 2>&1
```

## Настройки в .env

| Переменная | Что делает |
|---|---|
| `CONTENT_MODE` | `file` — посты из posts.txt, `ai` — генерация Claude |
| `POSTS_PER_DAY` | сколько постов в сутки |
| `ACTIVE_HOURS` | часы публикации через запятую, 0–23 |
| `JITTER_MINUTES` | случайный разброс ±N минут |
| `MAX_POSTS_PER_DAY` | предохранитель: жёсткий потолок, даже если что-то сломается |
| `DRY_RUN` | `true` — всё работает, но твит не уходит |

Если `POSTS_PER_DAY` меньше, чем часов в `ACTIVE_HOURS`, слоты берутся не подряд,
а распределяются по дню: при `ACTIVE_HOURS=10,15,20` и `POSTS_PER_DAY=2` бот
запостит в 10 и 20, а не в 10 и 15.

## Если что-то не работает

| Ошибка | Причина |
|---|---|
| `401 Unauthorized` | ключи неверные, с пробелами или отозваны |
| `403 Forbidden` | права Read вместо Read and Write, либо токены не перевыпущены после смены прав, либо текст — точный дубль недавнего твита |
| `429 Too Many Requests` | упёрся в rate limit, бот сам подождёт и повторит |
| `Нет связи с api.twitter.com` | интернет, прокси или файрвол. При публикации бот сам повторит 3 раза с паузами 30/60/120 сек |
| Пост не уходит, в логах тишина | проверь, что `DRY_RUN=false` |

Первым делом запусти `python main.py check` — он объясняет причину словами
и возвращает `0`, если ключи рабочие, и `1`, если нет. Расписание он печатает
в любом случае, даже когда до X не достучался.

Логи: `bot.log` в папке проекта.

## Чего делать не стоит

- **Не постить ссылки без нужды** — они дороже обычных постов примерно в 13 раз.
- **Не гнать объём.** Правила X про автоматизацию разрешают ботить свой аккаунт,
  но запрещают спам и повторяющийся контент. Аккаунт, который выдаёт 20 однотипных
  постов в день, улетает в бан независимо от того, что постинг идёт через официальный API.
  3–5 осмысленных постов в сутки — безопасный потолок.
- **Не использовать браузерную автоматизацию** (selenium и т.п.) вместо API — за это банят.
- **Не коммитить `.env`** — он в `.gitignore`, но проверь перед первым пушем: `git status`
  не должен показывать `.env`. А вот `history.json` коммитить нужно — это память бота
  о том, что уже опубликовано, и GitHub Actions сам возвращает её в репозиторий.
- **Не оставлять генерацию совсем без присмотра.** Модель может написать неудачную фразу,
  а отвечать за неё будет твой аккаунт. Заглядывай в `bot.log` хотя бы раз в неделю.
